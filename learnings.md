# Learnings

- **Official facts stay separate from visual context** — project, price, wait, and amenity records remain dated and source-linked; missing facts resolve to `unknown` instead of becoming invented matches. The geospatial backdrop must not silently change product data.
- **Ship processed geometry, not source extracts** — `scripts/build-map-assets.ts` converts URA and OSM inputs from ignored `work/geo-raw/` into the compact `public/map/` contract. Raw downloads are large, unstable publication inputs and do not belong in the repository.
- **Building height is a visual approximation unless tagged** — OSM `height` and `building:levels` win when present; other heights use deterministic bands. The UI and documentation must never describe the miniature as surveyed 3D data.
- **Flat map meshes require deliberate winding and normals** — triangles viewed from above need +Y winding and normals or Three.js back-face culling makes valid terrain appear missing.
- **Software WebGL needs a demand-rendered path** — headless Chromium and software renderers use snapped camera moves, no post-processing or shadows, and `frameloop="demand"`; this keeps interaction and E2E reliable without weakening the real-GPU experience.
- **The map communicates criteria, not a ranking** — every miss has equal visual weight, unanswered/unknown criteria are neutral, and selection improves inspectability without changing the match result.
- **Camera input needs one shared ownership path** — orbit, keyboard pan, wheel zoom, and scripted fly-to must update camera position and the OrbitControls target together. Wheel zoom is cursor-anchored and project selection derives its framing from the real 1 km scene radius plus HUD-safe insets.
- **Prefer honest area glyphs over false footprint matches** — amenity highlights use conservatively matched OSM polygons only when name, category, and location agree. Point-only or uncertain records remain explicit coordinate-area fallbacks instead of borrowing a nearby building.

- **Amenity groups are a presentation layer over official types** — the five user-facing groups (`lib/amenity-groups.ts`) own labels, palette and type membership; matching checks group membership, but every record keeps its official type for details and data. Stored individual types migrate to groups instead of invalidating the whole answer set.
- **Fit opacity is a rule, not a score** — `1 − 0.23 × misses` (100/77/54/31/8 %) is the only criteria encoding; selection adds a ring and emissive lift and never resets it. Results are grouped (fits / awaiting published data / trade-offs) in snapshot order, never ranked.
- **One typed view state for the right panel** — `lib/panel-view.ts` keeps `questions | results | project | amenity` with an explicit `returnTo`, independent of `selectedProjectId`, so amenity detail can replace the panel while the map keeps its focus and 1 km boundary.
- **HDB Pulse article bodies are client-rendered** — `curl` returns only the shell; render with headless Chromium (`work/`-style Playwright script) before auditing facts. As of 2026-08-28, November 2026 project names, prices, classification, coordinates and waits are unpublished; only published facts (Lakeview/Shunfu window and flat types, HFE deadline) were added.
- **Media provenance is data, not decoration** — `data/amenity-media.json` is generated from curated Commons picks with creator, licence, source and `depicts`; it is joined by amenity ID and never mixed into the official snapshot. Fonts are self-hosted OFL files via `next/font/local`; no runtime font or image fetch.
- **Restart Next development after a production build** — `next build` rewrites `.next` and invalidates a running `next dev` process. Restart the development server before Playwright, and clear inherited `CI` (`env -u CI npm run test:e2e`) when the suite should reuse the configured local server.
- **Canonical truth beats speculative AI files** — the durable discovery surface is visible, useful text with internal links, dated sources, matching JSON-LD, and crawl access. `/ai-info` states the product boundary for humans and answer engines; no `llms.txt` is added because it is not required for Google AI features and the wiki evidence did not establish it as a dependable standard.
- **Programmatic pages must earn their URL** — project pages are generated only for real records and expose unique published facts, explicit missing fields, nearby context, related projects, and official sources. The sitemap is derived from the same typed records and tested for exact coverage and duplicate paths.
- **Production canonicals must follow deployment identity** — `NEXT_PUBLIC_SITE_URL` owns a custom domain; Vercel's production hostname is the safe fallback. Local builds intentionally emit localhost URLs rather than guessing a public domain.
- **FAQ content is useful without rich-result theatre** — the visible FAQ and matching schema help users and machines understand the tool, but Google generally reserves FAQ rich results for authoritative government and health sites. The site makes no rich-result promise and does not imply government status.
- **Shared chrome must be literally shared** — matching two independently styled headers is fragile. The map and content routes now render the same `SiteHeader`, with one height, gutter, wordmark, and navigation order; an 834×734 browser test compares their actual coordinates.
- **Editorial structure beats generated-card repetition** — the useful anti-slop changes were subtractive: remove the rounded monogram, badge, eyebrow, accent stripe, broad shadow, and identical guide cards. Plain typography, rules, source dates, and a scannable guide list better fit a housing information service.
- **The product outcome is a defensible shortlist, not completed questions** — questions should expose chosen answers and plain reasons, then lead into a capped side-by-side comparison. “Finish narrowing” is a transition into decision work, not the end of the product.
- **Persist navigation intent, not just selected IDs** — a restored amenity view must retain both its project context and whether that project came from Questions or Results. Validate every nested return target before restoring it.
- **One filter must define every visible project surface** — map clusters, labels, project tray, counts, results, and selected-project context all derive from the same launch-stage subset so hidden selections cannot leave stale map boundaries or titles.
- **Ads stay subordinate to the decision tool** — use only named manual units: one in-article guide placement and one non-sticky content-footer placement. Keep Auto Ads off and keep the map, privacy page, and AI disclosure page free of ad placements.
- **Publisher configuration has a hard identity boundary** — public client and slot IDs may live in source/environment configuration, but bank, tax, identity, address/PIN, and payment-profile actions must be completed by the account owner.
- **Public contribution does not imply merge access** — outsiders may fork and open PRs, while `main` requires CI, an approving review, and code-owner review. `@radiansnail-1` owns all paths; administrator bypass remains available only to avoid locking out the sole owner.
